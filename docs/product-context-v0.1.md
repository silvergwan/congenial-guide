# 바카티오 제품 맥락과 안부 기능 제안

확인일: 2026-11-03 · 공식 공개 소개 기준

## 서비스명

- 현재 표기: **Vacatio Solution PMS / 바카티오 솔루션**
- 이전 표기: 파인호스트(FineHost). 공식 제품 소개에서 ‘구 파인호스트’로 명시한다.
- 파인스테이는 별도 B2C 숙소 예약 서비스다. PMS와 구분한다.
- 기존 `finehost.ai` 숙소 페이지는 조사 출처 URL로 보존한다. 해당 URL이나 파인스테이 노출만으로 현재 PMS 이용 고객이라고 판단하지 않는다.
- 명칭 변경의 정확한 시행일은 이번 확인에서 확보하지 않았다.

출처: [공식 비즈니스 소개](https://vacatio.us/business), [PMS 제품 소개](https://vacatio.us/business/finehost).

## 공식 소개에서 확인한 제품 구조

PMS는 예약·객실·운영 관리의 중심으로 소개된다. 예약 관리, 안내문자 자동화, 하우스키핑, 리포트, AI 운영비서를 설명하며 CMS·요금 관리·키오스크·스마트 IoT와의 연결을 강조한다. 비즈니스 소개는 독채·펜션부터 호텔까지 운영 형태별 구성을 제시한다.

이는 공개 제품 설명에 대한 확인이다. 실제 도입 숙소의 사용 기능, 외부 API 제공 여부, 연동 권한과 상용 동작은 검증하지 않았다.

## 우리 프로젝트의 위치 — 기획 제안

**안부: Vacatio Solution PMS의 예약·투숙 관리 흐름에 연결하는 선택형 안부 확인 기능 제안.**

공식 제품에 이미 존재하거나 제공하기로 확정된 기능이라는 뜻이 아니다. 현재 구현은 가상 데이터로 동작하는 독립 데모다.

| 연결 지점 | 제안하는 흐름 | 검증할 질문 |
|---|---|---|
| 예약·투숙 상세 | 예약 건에서 안부 신청 여부와 약속 시각 확인 | 별도 목록보다 기존 예약 화면이 편한가? |
| 고객 안내 | 안내 메시지에서 게스트가 직접 신청·변경·취소 | 메시지 추가가 유용한가, 부담인가? |
| 담당자 업무 | 유예시간 후 확인 필요 건을 담당자에게 배정 | 누가 언제 확인하며 부재 시 어떻게 인계하는가? |
| 조치 기록 | 연락 시도·게스트 응답·확인 근거를 예약과 함께 기록 | 중복 연락과 누락을 줄이는가? |

기존 안내 자동화와 연결할 가능성을 먼저 검증한다. AI 위험 판정이나 도어락·위치 데이터 수집을 전제로 삼지 않는다.

## 현재 데모와 다음 검증

여행객 신청·응답, 호스트 목록·상세·기록을 그대로 활용한다. 다음 설계 후보는 가상 예약 ID와 투숙 기간, 예약 상세에서의 진입점, 담당자 부재·인계다. 아직 추가 구현을 완료한 항목은 아니다.

조사 대상은 제주 독채 운영자를 중심으로 유지한다. 공식 제품이 호텔까지 포괄한다는 이유만으로 이번 조사 범위를 넓히지 않는다. 운영 방식과 PMS 사용 여부를 별도로 확인한다.

상용 연동을 가정하기 전에 신청 동의, 실제 담당 가능 시간, 연락 책임과 미해결 건 처리부터 검증한다. 수요 감소와 안전 효과는 계속 가설로 둔다.

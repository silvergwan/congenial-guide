# 조사 계획 v0.1

## 조사 목적

1. 안전 우려가 실제 숙소 선택에 영향을 주었는지 구체적 경험을 확인한다.
2. 게스트와 연락이 닿지 않을 때 호스트가 현재 하는 일과 부담을 파악한다.
3. 선택형 안부 확인의 수용성, 이해도, 운영 가능성을 검증한다.

## 진행 순서

| 단계 | 할 일 | 결과 |
|---|---|---|
| 1차 호스트 조사 | 이미 발송한 20곳의 회신과 반송 확인 | 유효 연락 수, 응답 수, 직접 사례 |
| 여행객 탐색 | 최근 제주 혼행 경험자 5명 내외를 목표로 모집 | 숙소 선택 과정과 실제 연락 경험 |
| 호스트 보완 | 실제 1인 투숙 경험자 3명 내외를 목표로 확보 | 처리 절차·시간·운영 조건 |
| 프로토타입 | 여행객과 호스트 역할별 과제 관찰 | 혼동 지점·미응답 오해·운영 부담 |
| 수정 | 가설별 증거와 반례 비교 | 문제 정의서 v0.2와 다음 실험 |

목표 인원은 탐색용 계획값이다. 모집·응답·검증이 완료되었다는 의미가 아니다.

## 호스트 표본

- 독채 운영자와 호텔 운영자의 답변을 분리한다.
- 1인 투숙을 받지 않는 곳은 혼행 감소 분석에서 제외하고 그 이유를 별도 기록한다.
- 가족·단체 중심, 여러 독채를 관리하는 운영자, 단독 1객실 운영자를 구분한다.
- 같은 운영자가 여러 숙소·객실을 운영하면 운영자 1명으로 집계한다.
- 2차 후보의 선정 근거와 연락 가능성은 [후보 검토](candidate-review.md)를 참조한다.
- 이메일 주소가 없다는 이유로 임의의 주소를 만들거나 다른 사업자의 메일을 쓰지 않는다.

## 질문 순서

현재 고객 구성 → 최근 구체적 경험 → 예약 변화와 근거 → 고객이 직접 말한 이유 → 현재 연락 절차 → 부족한 지원.

첫 탐색에서는 해결책을 먼저 설명하지 않는다. 이후 프로토타입을 보여주고 사용 행동을 관찰한다. '범죄 때문에 예약이 줄었죠?'처럼 결론을 유도하지 않는다.

## 이메일 운영

- [1차 원본](../templates/host-email-v0.1.txt)은 변경하지 않고 기록으로 보존한다.
- [2차 초안](../templates/host-email-v0.2.md)은 짧은 경험 확인부터 시작한다. 첫 메일과 질문이 달라졌으면 조사 버전을 기록한다.
- 첫 발송 뒤 3~5영업일을 회신 품질 검토 시점으로 제안한다. 자동 추가 발송 일정은 없다.
- 발송 상태가 불명확하면 보낸편지함의 조사번호로 확인한 후 처리한다.
- 반송과 연락 거절은 별도 기록한다. 미응답을 '문제 없음'으로 처리하지 않는다.
- 새 메일·후속 메시지를 보내는 것은 별도 실행 작업이며 이 저장소 설치만으로 발송하지 않는다.

## 여행객 모집

국내여행 커뮤니티 등의 게시 규칙을 확인한 후 개인 프로젝트임을 밝힌다. 자발적 참여, 최근 실제 제주 혼행 여부, 숙소 유형을 확인한다. 범죄·사고 피해 경험을 상세히 요구하지 않으며 답변을 건너뛸 수 있게 한다. 아직 커뮤니티에 모집 글을 게시하지 않았다.

## 분석

예약 기록 / 체감, 고객 직접 발언 / 운영자 추정, 혼행 / 전체 예약, 독채 / 호텔을 분리한다. 분석 방법은 [회신 분석 기준](reply-coding-guide.md)을 따른다.

공개 이메일에 응답한 소규모 표본은 제주 전체 시장을 대표하지 않는다. 연락 가능한 운영자·응답 의향이 있는 운영자에 편중될 수 있다.
